# Workflow: Bugfix

1. Classify with `SOLO_FOUNDER_CONTROL_PLANE.md` when the bug affects users, beta, support, security, data, revenue, vendor behavior, or launch readiness.
2. Reproduce or localize the bug.
3. Identify root cause before editing.
4. Fix narrowly.
5. Add or update a regression test.
6. Run targeted checks.
7. Link repeated bug/support patterns to feedback loop, decision sync, docs/runbook, or a stronger product fix.
8. Report residual risk.

Use premortem only if the bug reveals a broader launch/release/process risk.
