# Workflow: Growth Experiment

1. Classify the input with `SOLO_FOUNDER_CONTROL_PLANE.md`.
2. Define hypothesis, audience, user problem, channel, metric, window, owner, and stop condition.
3. Check current context: active GTM/pricing/ICP decisions, waitlist/beta metrics, content signals, docs as hypotheses, accepted debt, and approval gates.
4. Apply `.agent-os/BUSINESS_GTM_CONTRACT.md`: ICP fit, offer, channel, proof, CTA, activation/retention link, cost, support burden, claim boundaries, and reversal trigger.
5. Apply `.agent-os/FOUNDER_COMMUNICATION_CONTRACT.md` when the experiment uses founder-led content, personal brand, public story, social channels, testimonials, founder proof, audience building, or build-in-public.
6. Research competitors/benchmarks/platform policies if useful or if public claims, channel mechanics, creator authenticity, or platform behavior may change.
7. Run premortem if the experiment can affect positioning, pricing, trust, legal/compliance, deliverability, platform risk, creator brand, or founder reputation.
8. Implement the minimum viable experiment.
9. Instrument events and source of truth using `DATA_ANALYTICS_CONTRACT.md`.
10. Check privacy/consent/unsubscribe, vendor/subprocessor, public-claim, content-rights, and founder-support burden before launch.
11. Review outcome and decide keep/kill/iterate; sync durable business decisions and docs after evidence.
