# Workflow: Incident

1. Stabilize and stop user/business damage.
2. Classify with `SOLO_FOUNDER_CONTROL_PLANE.md` as incident/reliability/security/support risk.
3. Preserve evidence.
4. Identify impact and affected systems, data, vendors, users, support burden, and business/revenue risk.
5. Fix, rollback, restore, backfill, replay, disable, or scope away.
6. Verify recovery with user-facing evidence, logs/monitoring, data integrity checks, and support confirmation when relevant.
7. Run post-incident learning only after stabilization: root cause, prevention, detection, communication, docs/runbook updates, decision sync, and owner/date for follow-ups.

Premortem remains pre-decision. Incident review is separate and should not block urgent recovery.
