## Cierre académico de esta versión

El PDF/DOCX vigente está en [reentrega-2026-09-08-v2](https://github.com/mativelezx/umbra/releases/tag/reentrega-2026-09-08-v2). Sustituye para la entrega los archivos de la primera publicación; la etiqueta anterior se conserva como antecedente.

Se enlazó ese material desde Relevamiento, sin inventar empresa, empleados, entrevistas ni datos de usuarios. El cierre conserva la responsabilidad del autor y explica el aprendizaje técnico sin atribuir resultados no obtenidos. Las métricas, arquitectura y producto no se alteraron para aparentar cumplimiento.

La revisión conserva el nivel técnico de Ingeniería en Software: requisitos e historias con criterios, Scrum adaptado a trabajo individual, DER y diccionario, arquitectura, seguridad, costos, riesgos y evaluación del módulo propio. No se añaden microservicios ni tecnologías. El esqueleto antiguo de `thesis/` quedó marcado como histórico; no genera estos documentos.

Se repitieron el 8 de septiembre: 398 pruebas Vitest bajo Node 24.19.0, tipos, lint y 37 pruebas Python con el opt-in de pesos reales. La suite Python conserva advertencias por APIs deprecadas y métricas de fixtures pequeños; no son resultados de la evaluación académica del corpus. El barrido publicado comenzó a las 12:43 UTC: cuatro recorridos aprobados, 50 pantallas/estados, sin omisiones ni reintentos, sin desbordamiento horizontal ni hallazgos serios/críticos de axe. Usa la cuenta ficticia guardada y no consume nuevas generaciones de Claude. Una primera pasada falló por falta de espacio al guardar una captura; se liberó la caché local y se repitió completa.

La web respondió HTTP 200 y el servicio ML informó pesos cargados. Resend respondió con cero dominios: el correo externo continúa pendiente, no se certifica registro/recuperación/eliminación mediante buzones externos. Las verificaciones operativas admiten una demo académica supervisada, no una apertura masiva a usuarios.

La documentación se presenta como revisión del prototipo académico, no como una aprobación del CAE ni una validación psicológica. Las pruebas usan datos ficticios. La cuenta utilizada para el recorrido remoto se confirmó por administración: no constituye una prueba del registro por correo.

## Cómo repetir el cruce del documento

Descargar PDF y DOCX de la publicación de esta reentrega. Instalar `python-docx` y `pypdf` en un entorno Python propio y ejecutar desde la raíz:

```bash
python scripts/verify-thesis.py /ruta/TFG_Umbra_Velez_SOF01994.docx /ruta/TFG_Umbra_Velez_SOF01994.pdf \
  --repo . \
  --manifest docs/evidence/reentrega-2026-09-08/document-manifest.json \
  --pages docs/evidence/reentrega-2026-09-08/pages.json \
  --output /ruta/resultado-cruce.json
```

Para repetir capturas de lectura, preparar una cuenta ficticia con resultados guardados y proporcionar `E2E_SYNTHETIC_PASSWORD` por variable privada. Revisar `e2e/release-evidence.spec.ts`; exige opt-in y restringe el destino. No publicar esa variable ni ejecutar pruebas pagas sin autorización.
